## 五、v17 vs v18 最大差异（5条）

1. **format_scale 大幅降低（1.2→0.7）是最重要的超参变化**：此次改动使格式奖励对总 reward 的贡献从 v17 最大约 1.2 降至约 0.7，模型格式化结构输出的激励减少，可能导致推理链路组织能力下降，直接影响逻辑严谨性（-7.1 分）。
   - 证据：sql_agent.py vs sql_agent_v18.py diff，第 323-324 行。

2. **新增 EvidenceSafety 模块引入了双向干扰信号**：该模块意在惩罚无根据的强结论，但实验结果显示证据回答一致性退步 -6.6 分，说明其负向惩罚（对有真实引用但无 SR/RCT 的情况扣 0.12）可能让模型在有据可依时也变得过度保守，导致回答与证据的呼应弱化。
   - 证据：sql_agent_v18.py check_evidence_safety() 函数逻辑 + 评测维度对比。

3. **LR 降低（7e-7→5e-7）+ KL 增强（0.08→0.10）使训练更保守**：v18 的学习步长更小、对偏离 reference model 的约束更强，在保证训练稳定性的同时也限制了模型的探索空间，可能导致能力提升上限降低。
   - 证据：train_sql_agent.py vs train_sql_agent_v18.py diff，第 107, 109, 173 行。

4. **训练数据集扩充（train_v18_full_weighted.parquet，+6.8%）带来了信息全面性的唯一改善（+2.0 分）**：这说明数据覆盖度扩充方向有效，但 Reward 设计的变化抵消了大部分数据质量提升带来的收益。
   - 证据：文件大小对比（221KB vs 236KB）+ rule_completeness_depth 得分对比。

5. **回答分布变得更不稳定（标准差 7.9→10.2，最低分 47.8→27.3）**：v18 的最低分出现了接近 27.3 的极端低分，说明某些问题类型上出现了严重失误，可能与 EvidenceSafety 的惩罚信号干扰了模型在特定证据场景下的正常输出有关。
   - 证据：两版 summary 的 score_min/std 对比。

## 六、v19 建议

1. **恢复 format_scale 至 v17 水平（1.2），或采用阶梯式调度**：考虑在训练前期保持较高 format_scale（1.0~1.2）保证结构化输出质量，后期逐步降至 0.8，而非一次性降至 0.7。逻辑严谨性是 v18 最大退步点，与 format 权重直接相关。

2. **EvidenceSafety 模块需重新设计惩罚触发条件**：建议将"有真实引用但无 SR/RCT 时使用强结论词"的惩罚（-0.12）阈值提高，或仅在 fabricated_ids > 0 时触发，避免对有合理指南引用的结论误罚。重点测试在 rule_evidence_answer_consistency 维度的影响。

3. **维持 LR 在 7e-7 附近，适当增大 KL coef 至 0.09**：v18 将 LR 降至 5e-7 使训练过于保守，v19 可恢复至 6e-7~7e-7，同时 KL coef 保持在 0.09（介于 v17 的 0.08 和 v18 的 0.10 之间），兼顾稳定性与探索能力。

4. **增加对逻辑严谨性的专项 reward 子项**：在 correctness_reward 中增加一个轻量的论证连贯性奖励——例如检测答案中"因为…所以…""证据表明…因此…"等推理连接词的出现频率，为逻辑链路完整性提供正向激励信号。

5. **在 v18 step400 基础上继续训练并重新评测**：当前 v18 已到 step 407，原始 val_peak 在 step300，建议完成全部 460 步后用 step400 版本重评，确认是否有进一步改善（v18 step300→400 阶段 training/reward 均值仍稳定在 3.36~3.43，说明训练仍在收益区间内）。
