# 07 · 结论与后续建议

## 一、核心结论

1. **模型版本**：v14 `global_step_336` 已 GRPO 崩溃，不可用；**v17 是可用基线**，能产出结论正确、格式规范、引用真实、零幻觉的循证回答。
2. **能力评估**：作为自训练 14B 模型，v17 的检索架构、循证范式、分层引用**已达到可用水准**，与线上生产版**核心结论一致**。
3. **与线上的差距**：主要在**证据颗粒度（具体 RR/CI/试验名）、临床 nuance、决策表格化、证据卡可视化**；根因是**检索规模差异**（线上 top10 不截断 vs 本地 top2+1500截断）与可能的更大模型/更强工程，**而非检索或模型基本能力**。

## 二、立即可做（低风险）

1. **统一以 v17 为基线**，停用 v14 `global_step_336`。
2. 部署/评测 v17 必须带：
   - `tool_choice="search_embedding_db"`（vLLM 0.7.3 不支持 `"required"`，用具名工具）；
   - 采样 `temperature=0.7, top_p=0.8, extra_body={repetition_penalty:1.05, top_k:20}`（防退化）。
3. checkpoint 选择流程中加入**格式遵循率 / 引用真实率 / 重复率**自动指标，及早发现 mode collapse。

## 三、缩小与线上差距（中等风险，需验证）

1. **保守放大检索**（甜点区）：`max-model-len 32768` + 每库 `top7~8` + 去 1500 截断 → 证据量与线上同量级，原生上下文、显存无压力。
   - ⚠️ 须实测 OOD 退化（重复率、lost-in-the-middle、引用真实率）。
2. **输出工程化**：在 prompt / 后处理中加入"临床决策表格"模板与证据卡渲染，向线上呈现形式对齐。

## 四、认真对齐线上质量（高投入，正路）

1. **按 top10 / 不截断的检索配置重新训练一版**，使训练与推理证据规模一致，从根上解决 OOD。
2. 评估是否需要**更大底座**（线上详细度可能部分来自更大模型）。
3. 若要 top10×4=40 篇不截断常态化 → 训练与推理都需 ~48K 上下文（YaRN），并评估长上下文训练成本。
